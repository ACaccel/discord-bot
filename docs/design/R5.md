# R5 — i18n catalog 路徑反耦合（詳細設計）

## 1. 概要

本文件對應 [`docs/proposal.md`](../proposal.md) §8 與
[`docs/high-level-design.md`](../high-level-design.md) §8。

`src/core/i18n/catalog-loader.ts` 目前以
`path.resolve(__dirname, '..', '..', 'i18n', 'locales')` 反推內容層
（`src/i18n/locales`）的位置。`core` 不該感知下游層的部署位置——這是分層
契約的逆向耦合。R5 的範圍是「介面收窄」：把 `LoadCatalogOptions.localesDir`
從 optional 改為必填、移除 `DEFAULT_LOCALES_DIR`，並把「locales 在哪裡」
的知識遷移到合成根。

R5 不新增 component、不改動 catalog 內容、不改 i18next 設定。共通設計原則
依 [`docs/design.md`](../design.md) §2。

## 2. 設計目標

源自 proposal §8.4 + HLD §8.2：

1. **零硬編碼路徑於 core**：`grep -rn "'i18n'" src/core` 結果為空。
2. **編譯期擋下遺漏**：`LoadCatalogOptions.localesDir` 為必填；呼叫端忘記
   注入將是 TypeScript 編譯錯誤，非執行期 fallback。
3. **錯誤訊息保持 actionable**：保留現有 `fs.existsSync` 守衛，路徑錯誤
   時拋出包含實際 `dir` 字串的可診斷錯誤。
4. **既有測試 fixture 行為不變**：`test/unit/core/i18n/catalog-loader.test.ts`
   已顯式注入 `localesDir`，不需修改。
5. **不引入新設定檔**：不建立 `i18n.config.json` 或環境變數——
   `path.resolve(__dirname, ...)` 已足夠表達合成根的部署知識。

## 3. 元件結構

### 3.1 變更概覽

| 介面 / 常數                         | 改前                                                    | 改後                                  |
| ----------------------------------- | ------------------------------------------------------- | ------------------------------------- |
| `DEFAULT_LOCALES_DIR`               | module-level const，`__dirname` 反推 `src/i18n/locales` | **移除**                              |
| `LoadCatalogOptions.localesDir`     | `readonly localesDir?: string`                          | `readonly localesDir: string`（必填） |
| `loadCatalogResources(options?)`    | 參數 optional，未傳則走 `DEFAULT_LOCALES_DIR`           | 參數**必填**，無預設 fallback         |
| `createDefaultTranslator(options?)` | 參數 optional                                           | 參數**必填**                          |
| `BaseBot` 取得 `localesDir` 之方式  | `buildHost` 內 `createDefaultTranslator()` 無參數呼叫   | 由 ctor 注入（見 §3.3）               |
| `src/deploy.ts`                     | `createDefaultTranslator()` 無參數                      | 由呼叫端以 `path.resolve` 計算後傳入  |

### 3.2 TypeScript 骨架

```ts
// src/core/i18n/catalog-loader.ts
import * as fs from 'node:fs';
import * as path from 'node:path';

import { I18NextTranslator, type CatalogResources } from './i18next-translator';
import { DEFAULT_LOCALE, type Locale, type Translator } from './translator';

const NAMESPACES = ['commands', 'errors', 'replies'] as const;
type Namespace = (typeof NAMESPACES)[number];

// DEFAULT_LOCALES_DIR removed — core no longer knows where content lives.

export interface LoadCatalogOptions {
  /** Filesystem path to the locales root. Required: composition root must inject it. */
  readonly localesDir: string;
  /** Override the fallback locale; default = {@link DEFAULT_LOCALE}. */
  readonly fallbackLocale?: Locale;
}

export const loadCatalogResources = (options: LoadCatalogOptions): CatalogResources => {
  const dir = options.localesDir;
  if (!fs.existsSync(dir)) {
    throw new Error(
      `loadCatalogResources: locales directory not found at "${dir}". ` +
        'Set LoadCatalogOptions.localesDir to the deployed locales root.',
    );
  }
  // ... unchanged read loop ...
};

export const createDefaultTranslator = async (options: LoadCatalogOptions): Promise<Translator> => {
  const resources = loadCatalogResources(options);
  return I18NextTranslator.create(resources, options.fallbackLocale ?? DEFAULT_LOCALE);
};
```

### 3.3 Composition root 改寫

合成根有 5 處需要注入 `localesDir`：4 個 bot 啟動入口
（`src/bot/{nijika,konata,tomori,msg-archive}/index.ts`）與 1 個
`src/deploy.ts`。

**決策：路徑常數放在 `BaseBot` 內，而非每個 bot 的 `index.ts`。**

理由：

- `BaseBot`（`src/bot/index.ts`）本身就是合成根的核心 collaborator，所有
  bot 共享同一個 monorepo 佈局（`src/bot/index.ts` → `src/i18n/locales`），
  其 `__dirname` 對所有 bot 一致。在合成根層內部選最合適的單一持有者
  即可；HLD §8 並未硬性要求「每個 bot 的 `index.ts` 都得計算一次」，
  只要求「core 不知道」。
- 若放在每個 `bot/<name>/index.ts`，4 個檔案會各自重複
  `path.resolve(__dirname, '..', '..', '..', 'i18n', 'locales')`，
  DRY 與單一事實源都更差，且若日後重組 `src/bot` 子目錄深度，4 處都要
  同步修改。
- 仍滿足介面收窄目標：`LoadCatalogOptions.localesDir` 對 `core` 仍是
  必填、無預設；分層契約由「`BaseBot` 屬合成根層，可以知道 `src/`
  佈局」這條規則承擔。

具體做法——`BaseBot` 不在類別內部硬編碼路徑，而是新增 ctor 參數
`localesDir: string` 並透過私有 helper 注入；計算路徑的工作仍由
`bot/<name>/index.ts` 呼叫一支共用 helper 完成，使「合成根知道路徑」這
件事顯式。

```ts
// src/bot/locales-dir.ts (new helper, 屬合成根層)
import * as path from 'node:path';

/**
 * Resolve the deployed locales root from this composition-root file's
 * own location. `__dirname` here is `<dist-or-src>/bot`, so up two
 * levels lands on `<dist-or-src>` and `/i18n/locales` is the canonical
 * catalog root used by every bot.
 */
export const resolveLocalesDir = (): string => path.resolve(__dirname, '..', 'i18n', 'locales');
```

```ts
// src/bot/index.ts (BaseBot — relevant diff)
import { resolveLocalesDir } from './locales-dir';

export abstract class BaseBot<TConfig extends Config = Config> {
  private readonly localesDir: string;

  protected constructor(/* ...existing... */, localesDir: string = resolveLocalesDir()) {
    // ...
    this.localesDir = localesDir;
  }

  private setupTranslator = async (): Promise<Translator> =>
    createDefaultTranslator({ localesDir: this.localesDir });

  // buildHost calls `await this.setupTranslator()` in place of the old
  // inline `await createDefaultTranslator()`.
}
```

`bot/{nijika,konata,tomori,msg-archive}/index.ts` 不需要逐一改寫
建構子呼叫——ctor 的 `localesDir` 參數有合成根層的預設值
`resolveLocalesDir()`，預設值的計算位置位於 `src/bot/`（合成根），
core 仍完全不知情。需要客製 catalog 位置（例如未來 npm 套件化部署）
的 bot 可顯式覆寫該參數。

`src/deploy.ts` 同樣 import `resolveLocalesDir` 並顯式傳入
`createDefaultTranslator({ localesDir: resolveLocalesDir() })`。

### 3.4 Design Pattern 採用

- **Constructor Injection / Explicit Dependency**——`localesDir` 改由
  外部注入而非 module-level 常數，符合「依賴顯式、可替換」原則。
- **Interface Tightening**——將 optional 欄位收為必填屬於 narrowing
  契約；舊呼叫端在編譯期即被擋下，無需 runtime 偵測。
- **無新 Pattern**——R5 不引入 Strategy、Factory 等新抽象；HLD §8.2
  明示這是「邊界收窄」而非「新元件」。

## 4. 介面契約

`loadCatalogResources(options: LoadCatalogOptions)`：

- **前置條件**：`options.localesDir` 必須為合法檔案系統路徑。
- **後置條件 / 失敗**：路徑不存在時拋出 `Error`，訊息包含實際 `dir`
  字串與修復提示（「Set LoadCatalogOptions.localesDir to the deployed
  locales root」）。
- **冪等性**：純讀檔；同一 `dir` 連續呼叫結果一致。

`createDefaultTranslator(options: LoadCatalogOptions)`：

- **前置條件**：同上。
- **後置條件**：回傳已 `init` 完成的 `Translator`；`fallbackLocale`
  未指定時退化為 `DEFAULT_LOCALE`（`zh-TW`）。

## 5. 元件互動

新呼叫鏈：

```
bot/<name>/index.ts          (合成根入口)
   ↓ new Subclass(client, token, …, [localesDir?])
BaseBot(ctor)
   ↓ this.localesDir = localesDir ?? resolveLocalesDir()
BaseBot.buildHost
   ↓ await this.setupTranslator()
BaseBot.setupTranslator
   ↓ createDefaultTranslator({ localesDir: this.localesDir })
core/i18n/catalog-loader::createDefaultTranslator
   ↓ loadCatalogResources({ localesDir })
I18NextTranslator.create(resources, fallbackLocale)
```

`deploy.ts` 走平行的捷徑（不經 `BaseBot`）：

```
deploy.ts → resolveLocalesDir() → createDefaultTranslator({ localesDir })
```

**子類覆寫檢查**：`grep -n "buildHost\|setupTranslator\|createDefaultTranslator"
src/bot/*/*.ts` 結果為空——`Nijika` / `Konata` / `Tomori` / `MsgArchive`
皆未覆寫 `buildHost`，故新增私有 `setupTranslator` 不會破壞既有子類。
新增 ctor 參數採尾端 + 預設值，現有 4 個子類 `super(...)` 呼叫亦無需改動。

## 6. 測試設計

### 6.1 測試驗收點

| #   | 測試目標                                                              | 方式                                                                                                                                          |
| --- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `loadCatalogResources()` 無 `localesDir` ➜ TypeScript 編譯錯誤        | `tsc --noEmit` 既有 gate；無需專屬 runtime 測試                                                                                               |
| 2   | `loadCatalogResources({ localesDir: '<不存在>' })` ➜ actionable Error | 既有 `test/unit/core/i18n/catalog-loader.test.ts` 已涵蓋（保留）                                                                              |
| 3   | `createDefaultTranslator({ localesDir })` 可解析 `zh-TW` / `en`       | 既有 `catalog-loader.test.ts` 已涵蓋（保留）                                                                                                  |
| 4   | catalog completeness test 持續綠燈                                    | `test/i18n/catalog-completeness.test.ts` 已顯式注入路徑，不受影響                                                                             |
| 5   | `test/i18n/catalog-runtime.test.ts`                                   | **需修改**：將 `loadCatalogResources()` 改為傳入測試用的 `localesDir`（即實際 `src/i18n/locales` 絕對路徑），與 `catalog-loader.test.ts` 對齊 |

### 6.2 Fixture / Mock 策略

不引入新 mock。既有測試使用 `os.tmpdir()` 建立 fixture，再寫入最小
namespace JSON 後傳入 `localesDir`，本輪沿用。`catalog-runtime.test.ts`
需以實際內容層（`path.resolve(__dirname, '..', '..', 'src', 'i18n',
'locales')`）作為注入值——測試檔本身亦屬合成根層，可以知道專案佈局。

### 6.3 整合面

現行測試樹缺少「四個 bot 真實啟動載入 catalog」的 smoke test。本輪
**建議**新增 `test/integration/i18n/bot-bootstrap.smoke.test.ts`：對
`nijika` / `konata` / `tomori` / `msg-archive` 各建構一次（mock Discord
`Client` / Mongo 連線），呼叫至 `buildHost` 為止並斷言 `bot.translator`
能解析任意已知 key。此項屬建議而非阻塞——若 sprint 容量不足，可單獨成
追蹤任務，不影響 R5 的驗收。

## 7. 與其他 R 的整合點

- **R1（BaseBot 拆解）**：R1 會把 `buildHost` 的職責拆給新的 collaborator。
  R5 新增的 `setupTranslator` 私有方法與 ctor 參數會跟著遷移到對應的
  collaborator。落地順序依 proposal §3：R1 先、R5 後；R5 落在 R1 拆解
  完成的結構上，避免雙重 diff。
- **R6.5（`src/bot/index.ts` import 整理）**：R5 在 `src/bot/index.ts`
  新增一行 `import { resolveLocalesDir } from './locales-dir';`，與 R6.5
  的 import 排序同檔；R6.5 收尾時順帶確認新 import 位置正確即可。
- **其餘 R**：無互動。

## 8. 不做的設計決策

延伸自 proposal §8.3，明確不做：

1. **不引入 `i18n.config.json`** 或任何新設定檔描述 locale 位置——
   `path.resolve(__dirname, ...)` 已是合成根層最自然的表達。
2. **不改 catalog 內容、結構、namespace 列表、i18next 設定**——R5 純
   為介面收窄。
3. **不把整個 `Translator` 實例由 composition root 傳進 `BaseBot`**——
   只傳 `localesDir: string`；`Translator` 的 async build 仍歸 `BaseBot`
   擁有，避免合成根扛 i18next init 的非同步副作用。
4. **不改為 lazy load**——啟動期同步建構 catalog 仍是設計選擇，理由
   與 `catalog-loader.ts` 既有註解一致（ts-node / 無 bundler 場景下
   `readFileSync` 一次性開銷可接受、靜態路徑解析最單純）。
5. **不引入環境變數**（如 `LOCALES_DIR`）——避免在「明明是部署佈局
   常數」上加 runtime 變數源，徒增配置面。
