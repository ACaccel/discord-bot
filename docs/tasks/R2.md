## 10. Self-review summary (R2 implementer)

Reviewer agents (`architecture-reviewer` / `reliability-reviewer` /
`type-system-reviewer`) were not available as Agent invocations in this
dispatch, so each rubric was self-checked against the corresponding
skill files. Verdicts:

- **architecture-reviewer (self)**: PASS. The `registerInstance` facade
  is a single narrow write surface on `PluginInitContext`; the
  `LifecycleHost` widens by exactly one read-only `container` field;
  plugins still receive only the typed-token resolver. Layer
  dependency direction (`bot → plugins → handlers → infra →
persistence → core`) is preserved. The two new tokens are declared
  alongside the existing ones; no new alias / barrel was added.

- **reliability-reviewer (self)**: PASS. The phase guard captures
  `this` in a closure so a plugin that smuggles the init ctx into a
  later phase still trips the guard; `runInit` / `runStart` /
  `runReady` each reset `this.phase = 'running'` in `finally`, so a
  late-resolving async tail after a critical-init failure cannot
  register late. Duplicate-token semantics piggyback on the existing
  `DuplicateRegistrationError`; the failure path is the host's normal
  "disabled plugin" flow. Pre-existing test (`host-lifecycle.test.ts`)
  was updated to supply the new `container` field on the test
  `LifecycleHost`.

- **type-system-reviewer (self)**: PASS. `RegisterInstance` is a
  generic function type with `<T>` flowing from `ServiceToken<T>` to
  `instance: T`; the container's invariance brand keeps
  `ServiceToken<Dog>` non-assignable to `ServiceToken<Animal>`.
  Compile-time check in `lifecycle-guard.test.ts` proves
  `registerInstance` is absent from `PluginStartContext` and
  `PluginRuntimeContext`. Strict TypeScript (`tsc -p
tsconfig.strict.json`) passes.
