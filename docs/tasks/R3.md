## 10. Self-review (R3 implementer)

外部 reviewer agents（`architecture-reviewer`、`config-and-security-reviewer`）
在當前環境未提供 Agent tool，依任務指示改以自我審查並記錄如下。

### architecture-reviewer 視角 — PASS

- 分層方向未反轉：`core/plugin` import `core/ioc` 仍是 core 內部 sibling
  關係，符合既有「`core/ioc` 為 leaf、`core/plugin` 可依賴 `core/ioc`」
  的設計（見 project-conventions §1）。
- Plugin layer 由 ESLint 規則保證**只能**經 `core/plugin` 取得 IoC 表面；
  容器寫入面（`ServiceContainer` / `createContainer` / `token()`）
  刻意不從 barrel 暴露，composition root 專屬權限維持完整。
- 8 個 plugin.ts 的 import 改寫不影響行為等價性：TOKENS / ServiceToken /
  Resolver 在 `core/plugin` re-export 後即同一 binding，runtime 無差異。

### config-and-security-reviewer 視角 — PASS

- 新增的 ESLint block 與既有 service-locator guard 對 file glob 無交集
  （前者限 `src/plugins/**`、後者限 application/domain/i18n/persistence/
  infra/handlers），不會出現「同一檔案兩條訊息」的重複違規。
- ESLint pattern group 涵蓋 4 種寫法：`**/core/ioc`、`**/core/ioc/*`、
  `@core/ioc`、`@core/ioc/*`，未來不論 plugin 改用相對路徑或 alias 都會被擋。
- `test/**` 已既有 `no-restricted-imports: 'off'` block 覆蓋，plugin 測試
  夾具（含本 R 新增的 fixture 測試）不會被新規則卡住。
- 規範文字 verbatim 鎖定（sha256 一致）—— 未來如需修訂可一次性 grep + sed
  四份文件保持同步，避免文件漂移。
