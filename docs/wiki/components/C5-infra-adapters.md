# C5 — Infra Adapters

## Responsibility

Isolates third-party SDKs behind typed adapters so the rest of the codebase depends only on stable interfaces. Five families: Mongo connections, LLM providers, link-preview providers, the X (Twitter) timeline source, and small Discord-side adapters.

## Mongo

`src/infra/mongo/connection-manager.ts` exposes `ConnectionManager` with two implementations: `MongoConnectionManager` (real Mongoose) and `StaticConnectionManager` (test injection).

- `getConnection(guildId)` opens or returns the cached connection for a guild.
- Failure classification reuses `isTransient(error)` from `src/persistence/error-translator.ts` (`DATABASE_TIMEOUT` / `DATABASE_NETWORK` are transient, others persistent).
- Transient failures retry with bounded exponential backoff via `RetryPolicy` (default: 3 attempts, 200 ms initial, 2 s cap; injectable through the constructor).
- When retries are exhausted or a persistent error occurs, the manager marks the `guildId` disabled with a generated `traceId` and logs one operator-level line.
- `isDisabled(guildId): DisabledGuildState | undefined` exposes the disabled state (`traceId` plus the classified `DatabaseError`) for handlers and BaseBot to read; subsequent `getConnection` calls short-circuit with the same error. `close` / `closeAll` clear the marker.
- Bots sharing the same base URI share one disabled set (one physical database, one failure).

## LLM

`src/infra/llm/` implements the Provider Strategy:

- `types.ts` — `LlmProvider` interface plus shared request/response shapes. `DEFAULT_MODELS` seeds each provider's cheapest current chat model (xai `grok-4-1-fast-non-reasoning`, openai `gpt-5-nano`, anthropic `claude-haiku-4-5`, gemini `gemini-2.5-flash-lite`); `DEFAULT_SETTINGS` enables web search by default.
- `openai-provider.ts`, `anthropic-provider.ts`, `gemini-provider.ts`, `xai-provider.ts` — concrete `LlmProvider` implementations.
- `registry.ts` / `default-registry.ts` — provider registry assembly.
- `llm-service.ts` — facade used by the `llm-chat` plugin.
- `models-catalog.ts` — `ModelCatalog` (pure cache plus API-key map). Registered via `ctx.registerInstance(TOKENS.ModelCatalog, ...)` inside `LlmChatPlugin.init`; consumed by handlers through `bot.modelCatalog?.list(provider)`. `list(provider)` is the synchronous cache view capped to the 25-option Discord select-menu limit (built for the 3-second window); `listLive(provider)` is the awaited authoritative fetch consumed by the default-model resolver and returns the _full_ uncapped list (the menu cap must not hide the cheapest model from price ranking), while the cache it refreshes stays capped.
- `default-model-resolver.ts` — `DefaultModelResolver`. Holds the per-provider default chat model, seeded from `DEFAULT_MODELS` and re-derived by `refresh()` to the cheapest still-listed priced model (live list ∩ `pricing.ts`). Conservative: a failed/empty fetch or an all-unpriced list keeps the previous default. Registered via `ctx.registerInstance(TOKENS.DefaultModelResolver, ...)` in `LlmChatPlugin.init`; consumed by `ai_whitelist_add` through `bot.defaultModelResolver?.current(provider)`.
- `error-translator.ts` — translates provider errors to `LlmProviderError`.
- `pricing.ts` — token-cost lookup table plus `cheapestModel(candidates)` (lowest input price, output price as tie-breaker, unpriced candidates ignored).
- `selfhosted-client.ts` — `SelfHostedLlmClient`, a standalone outbound adapter for a lightweight self-hosted LLM HTTP endpoint (consumed by the `llm-auto-reply` plugin, C8). It deliberately does **not** implement `LlmProvider`: the endpoint takes a single baked `user` message (`{ messages: [{ role, content }] }`) and returns `{ status, response }` with no API key, model, or temperature. `reply(transcript)` returns `Result<string, ExternalServiceError>` — timeout, HTTP error, malformed body, and non-`success` status are all mapped into the shared `errors:llm.*` taxonomy so callers stay silent on failure. Uses `axios` with a per-request timeout and validates the response body with zod.

## Link Preview

`src/infra/link-preview/` implements a second Provider Strategy, mirroring the LLM layer, for the `social-link-preview` plugin (C8). A provider produces neutral data only — Discord-specific assembly (embeds, replies, suppression) belongs to the consuming plugin, so this layer stays free of message I/O.

- `types.ts` — the `LinkPreviewProvider` Strategy (`canHandle(url)` pure predicate + `build(url, ctx)` returning a `Result`) and the `LinkPreviewResult` discriminated union. The union carries the two preview mechanisms: `{ kind: 'rewritten-url' }` (reply with an embed-proxy URL so Discord unfurls a playable video — a bot-authored embed cannot render playable video) and `{ kind: 'card' }` (a neutral `PreviewCard` the plugin renders into a static embed). `build` returns `Ok(null)` for "matched the host but not previewable" and `Err(LinkPreviewError)` for upstream/parse failure; it never throws.
- `registry.ts` — `LinkPreviewProviderRegistry`. Unlike the LLM registry (keyed by enum name), providers are matched against an arbitrary URL, so it holds an ordered list and `findProvider(url)` returns the first whose `canHandle` accepts it. Registration order is priority.
- `default-registry.ts` — `createDefaultLinkPreviewRegistry(deps)` wires every provider in priority order (one line each). Each rewrite provider takes a priority-ordered `proxyHosts` LIST and shares one `OgClient`; `enabledProviders` is the per-source kill-switch. **There are no built-in host lists**: the six `*ProxyHosts` fields of `LinkPreviewRegistryDeps` are **required** dependencies fed from the operator's `social_link_preview` block (C11). Embed-proxy domains are third-party services whose availability and policies change far faster than this project ships a release, so a list baked into code would keep probing a host that went dark months ago until someone cut a release; requiring the field is also what forces a newly added rewrite provider to be handed a configured list rather than inheriting a stale built-in one. The recommended, audited values ship in each bot's `config.example.json` (C11).
- `providers/rewrite-provider.ts` — `createRewriteProvider(spec)` Template Method shared by the six URL-rewrite providers. It is no longer a pure string transform: `build` **validates before posting** — it probes each `proxyHost` in order, fetching the candidate's OpenGraph via `OgClient` (Discord crawler UA), and picks the best by score (`scoreMeta`), a four-tier ladder — **video > image > weak-image > text**, else `none`: a host with `og:video` wins immediately (playable); else the first host carrying a real post image; else the first host whose images are all low-value stand-ins; else the first text-only host; else `Ok(null)` so the orchestrator skips and **no bare/dead link is ever posted**. Neither image tier short-circuits the probe — a later host may still hold the video — and the loop's selection is `bestImage ?? bestWeakImage ?? bestText`. The **weak-image** tier exists because a proxy that cannot resolve a post's own media may answer with the **author's profile avatar** as `og:image`: technically an image, carrying none of the post's content, so it must lose to a proxy holding the real asset while still beating a bare title. A source opts in by supplying `lowValueImagePatterns` (an optional `RewriteSpec` field) — regexes matched against every image URL, demoting a candidate only when **every** image matches, so one real asset among stand-ins still scores `image`; with no patterns the scoring is unchanged. `scoreMeta` rejects **login-wall / not-found / proxy-error placeholders** (`isJunkPreviewTitle`, checked against both `og:title` and `og:description`: "Log in or sign up to view", "Content not found", vxReddit's "Failed to get data from Reddit" / bare proxy-name title, the Threads / viewthreads login wall in **both zh-TW and English** — "Log in with your Instagram", "使用你的 Instagram 登入", "Threads • 登入", "Threads • Log in" — ...) as `none` — a login-gated Facebook post or a Reddit-API-failed proxy returns an OG with only such a placeholder and no media, and scoring it as a text card would post a broken embed. The Threads markers are load-bearing rather than cosmetic: that wall carries a **generic Instagram logo as `og:image`**, so without them it scores as a usable image card and a "Log in" embed reaches the channel. Per-host probe failures log at debug (proxy flakiness is expected), never as `Err`. The whole sequence is bounded by `ctx.budgetMs` (cumulative) on top of `ctx.timeoutMs` (per host). `canHandle` stays a pure predicate.
- `providers/{twitter,instagram,threads,facebook,reddit,bilibili}.ts` — supply `matches`, the `proxyHosts` list, and `toProxyUrl` (Twitter/Instagram/Threads/Reddit drop the query; **Facebook preserves it** — `watch`/`permalink`/`story` ids live there; **Bilibili keeps only `?p=`**, the multi-part video selector, dropping bilibili tracking such as `spm_id_from`/`vd_source`). **Twitter/X leads with `vxtwitter.com`** (then `fxtwitter.com`, `fixupx.com`): `fxtwitter` now hands the Discord crawler **no `og:video` and no `og:image` at all** — it exposes the media through an `application/activity+json` alternate link a crawler does not follow — so a list headed by `fxtwitter` scores every X video text-tier, whereas `vxtwitter` serves a real `og:video` that 302s to a `video.twimg.com` mp4. **Facebook is a composed provider**, not a thin spec: it additionally (a) **expands `/share/<type>/<token>` short links** — the proxies cannot resolve the opaque share token and serve a login wall, so the provider first chases Facebook's browser-UA redirect to the canonical `/videos/`/`/reel/` permalink (`OgClient.resolveCanonical`) and probes THAT (the only form that yields a playable video), (b) **normalises a legacy album-photo permalink** (`/<owner>/photos/a.<albumId>/<photoId>/`, including the older multi-part `a.<id>.<id>.<id>` album tokens) to the id-addressed `/photo/?fbid=<photoId>&set=a.<albumId>` form before probing, because `facebed` resolves the path form to a **different, unrelated post** — real title, real media, another author — which no junk-marker filter can tell apart from a true preview, so the bot would embed a stranger's post under the poster's link, while the id form names the photo unambiguously (the album-photo shape is matched on the same footing as `/posts/`, `/videos/`, `/reel/`, `/watch/?v=`, `permalink.php`, `story.php`, `/share/…` and `fb.watch`, and a share link that expands onto it is normalised too); and (c) **falls back to a static OpenGraph card** when no proxy can preview a Facebook link (the probe returns `null`) — scraping Facebook's own OG, which Facebook serves to the Discord crawler UA, and rejecting login-wall placeholders via the shared `isJunkPreview`. Reddit matches comment permalinks (`/r/<sub>/comments/<id>`, bare `/comments/<id>`) and the mobile `/r/<sub>/s/<token>` share form across reddit host variants (`www`/`old`/`new`/`np`/`m`/`amp`); the audited list leads with `vxreddit.com` and falls back to `redditez.com`, both subject to Reddit's API limits, which is why a proxy answering with an error placeholder instead of media is skipped by the per-host validation. Instagram matches **both** the canonical `/reel|p|tv/<id>` and the author-prefixed `/<username>/reel/<id>` form (profile / share links use the latter; the prior anchored regex rejected it, so those links got no preview at all). Bilibili matches `(www.|m.)?bilibili.com` video pages (`/video/<BV…|av…>`) and rewrites onto its configured list (audited: BiliFix `vxbilibili.com`, `fxbilibili.seria.moe`, BilibiliEZ `bilibiliez.com`, `bembedfix.vercel.app`), **dropping the path's trailing slash** (vxbilibili 307-downgrades a `/video/<BV>/` request to `http://`, which Discord's crawler refuses, so the no-slash form must be posted). **Bilibili is also a composed provider** (like Facebook): it matches `b23.tv` / `www.b23.tv` short links, whose opaque token carries no video id, and first expands them to the canonical `/video/<BV|av>` URL via `OgClient.resolveCanonical` (browser-UA redirect chase), proxying only when the resolved URL is a bilibili video page and skipping silently otherwise (live / dynamic / article / bangumi targets, or a failed resolution); `?p=` is preserved through resolution, tracking query dropped. **Threads is the third composed provider**: besides `/@user/post/<id>` and `/t/<id>` it matches the anchored, token-bearing `/share/<token>` short link the Threads app's share button emits, whose opaque token the proxies cannot resolve (they serve a login wall for that path), and expands it itself — scanning the redirect chain (`OgClient.resolveRedirectChain`) for the **first `/@user/post/<id>` permalink hop, not the landing URL**, because the single-use `xmt` token is rejected on the follow-up request and Threads bounces the chase onward to `threads.com/?error=invalid_post`, and because the legacy `threads.net` host needs an extra 301 onto `threads.com` before the permalink even appears. The chase sends a **minimal UA** (`Mozilla/5.0 (Windows NT 10.0; Win64; x64)`): a full desktop-browser UA — including the one `resolveCanonical` sends — is answered with the single-page-app shell, HTTP 200 with no `Location` at all, so no server-side chase can observe the expansion. The resolved permalink is probed through the shared rewrite machinery with the `xmt` / `slof` share-attribution query stripped, and the result carries the original share link as `sourceUrl`. **Unlike Facebook there is no fallback**: an unresolvable share link returns `Ok(null)` and is skipped silently, because threads.com serves the Discord crawler UA that same login wall, so there is no self-scraped card to fall back on. **No single Threads proxy is good at every post type**, so the three healthy hosts divide the work and the list ordering plus the quality tiers pick the right one per post: `viewthreads.com` serves the real title and the real post image but never `og:video` (the best card for an ordinary still-image post, only a static thumbnail for a video), while `fzthreads.com` and `fixthreads.seria.moe` serve a fetchable `og:video` and `fzthreads.com` additionally resolves login-restricted posts. Their weakness is the mirror image — for a post carrying no media of its own they answer with the **author's profile avatar** as `og:image` — and that is exactly what this provider's `lowValueImagePatterns` (`/\/t51\.2885-19\//` and `/\/s150x150\//`, the fbcdn / cdninstagram avatar-rendition path segments) demote to `weak-image`, keeping any proxy holding a real post asset ahead of the avatar card while still ranking it above a text-only embed. Listing the real-asset proxy first costs nothing, because a video candidate short-circuits the loop from any position. Original-host-only matching excludes proxy hosts so an already-fixed link is left alone. Proxy domains are third-party services that churn — `facebookez.com` and `fixacebook.com` are domain-parked ad-network shells, `fixthreads.net` and the `threadsez.*` hosts no longer resolve, `vxthreads.net` times out, `rxddit.com` 502s on every post — which is why the lists are operator configuration and why every candidate is validated before it is posted: the priority list + validation makes the layer self-correcting, and a source recovers by itself the moment one of its proxies does.
- `providers/bahamut.ts` — a fetching provider for `gamer.com.tw` (no public proxy). Scrapes OpenGraph via `OgClient` and maps the first image into a `PreviewCard`.
- `og-client.ts` — `OgClient`, the SSRF-safe OpenGraph fetcher and the single network boundary (used by both validation and Bahamut). It mirrors what Discord's unfurl accepts at a proxy URL — **either** an HTML page with OpenGraph tags **or** a redirect (for a bot UA) straight to a `video/*` / `image/*` file Discord embeds directly. So the response is **streamed** and classified by its final `Content-Type`: a media type is itself a playable preview and **no body is downloaded** (a reel `*.mp4` can be many MB); otherwise the body is read only up to `</head>` (or a byte cap) and `parseOpenGraph` runs — fixing both IG failure modes the old buffered fetch hit (`kkinstagram` redirects the bot UA to a multi-MB `*.mp4`, and `uuinstagram` lands on a ~900 KB `instagram.com` page; the prior `maxContentLength` body cap rejected both, so IG returned nothing). `axios` follows up to `SAFE_MAX_REDIRECTS` (3) hops with a `beforeRedirect` guard (`isUnsafeRedirectHost`, exported + unit-tested) that refuses any hop to a private / loopback / link-local / unspecified / CGNAT IP (v4, v6, IPv4-mapped/compatible, NAT64), an internal hostname (incl. trailing-dot FQDN forms), or a non-`http(s)` scheme — so a crafted redirect to e.g. `169.254.169.254` is blocked. Each redirect hop's target is recorded; when the body fetch itself fails but a hop targeted a media file (`*.mp4`/`*.jpg`/…), it still counts as a hit — because **Discord**, not the bot, performs the unfurl, so a CDN our host cannot reach (datacenter-IP peering) but Discord can must not be a false negative. The default UA is the Discord crawler UA `Discordbot/2.0`. A separate `resolveCanonical(url, timeoutMs, provider?)` method follows the same SSRF-guarded redirect chain under a plain **browser** UA (Facebook only redirects a `/share/` short link to its canonical permalink for a non-crawler UA — the crawler UA gets a ready-made OG card at the share URL itself) and returns the post-redirect URL **without reading the body**, used by the Facebook provider to expand share links and by the Bilibili provider to expand `b23.tv` short links. Its optional `provider` argument (default `'facebook'`) tags any error on the Err rail with the calling source. A second resolver, `resolveRedirectChain(url, timeoutMs, provider, userAgent?)`, shares the identical SSRF-guarded chase (same `assertSafeRedirect` hop screening, same `SAFE_MAX_REDIRECTS` bound, body never read) but returns **every hop's target URL in order** instead of the landing URL — an empty array when nothing redirected. It exists because a source can mint a **single-use token** into its short link and reject that token on the follow-up request, bouncing the chase to a generic error page: the permalink then survives only as an **intermediate hop** and the landing URL carries nothing a proxy can preview (scanning every hop also absorbs a legacy-domain 301 that precedes the real expansion, at no extra cost to the caller). The `userAgent` override exists because redirect behaviour is routinely UA-discriminated — a source may answer a full desktop-browser UA with a **client-side-routed application shell (HTTP 200, no `Location` at all)** that only a browser can resolve, while a plainer UA still receives the 30x — so the caller picks the UA its source is known to redirect for; it defaults to the same browser UA `resolveCanonical` sends. A transport failure **after at least one hop was recorded still returns `Ok`** with the hops so far (the same salvage `fetch` performs for a media-file redirect — the recorded hops already identify the permalink); only a failure with no hops at all lands on the Err rail. Used by the Threads provider to expand `/share/<token>` short links. (DNS-rebinding of a public hostname to a private IP is the one residual SSRF gap, accepted as low-risk.) `parseOpenGraph(html)` (pure, exported) extracts all `og:image*`/`twitter:image` into `images[]`, the best `og:video*` into `video`, plus title/description/url/siteName, scanning only the `<head>` via a bounded regex (no HTML-parser dependency). Attribute values may be double-quoted, single-quoted, or **unquoted** — vxbilibili emits unquoted `property=`/`content=` attributes (and sometimes omits the space before the next attribute), which a quoted-only matcher would drop, silently losing the preview. A small bounded in-memory cache (TTL ~10 min, success-only, FIFO eviction) avoids hammering flaky proxies when the loop fans out or a link is reposted (a degraded-but-200 page is therefore cached for the TTL, briefly suppressing that URL's preview even after the proxy recovers — an availability trade-off). SSRF: the candidate host always comes from the operator-configured `proxyHosts` allow-list (or `canHandle`'s host set) — only the path/query is user-derived; worst-case latency per URL is bounded by `proxyHosts.length × timeoutMs`, capped by `validationBudgetMs`.
- `error-translator.ts` — maps `axios` transport/HTTP failures to `LinkPreviewError` (timeout / rate-limited / 5xx / fetch-failed) and constructs the "no usable OpenGraph tags" `LINK_PREVIEW_INVALID_RESPONSE`.

## X Feed

`src/infra/x-feed/` reads an X (Twitter) account's recent posts for the `x-media-feed` plugin (C8). Like the link-preview layer it returns neutral data only — choosing a channel, rendering, and posting belong to the consuming plugin.

- `types.ts` — the `XTimelineSource` Strategy (`fetchTimeline(handle, options?)` returning `Result<readonly XPost[], XFeedFailure>`) plus the normalised `XPost` / `XPostMedia` shapes. `XPost.id` is a **string**: X post ids are 64-bit and exceed `Number.MAX_SAFE_INTEGER`, so every comparison goes through `BigInt`. A Strategy rather than one concrete client because the ways to read a timeline differ sharply in cost and stability — swapping to X's metered official API is one new file here plus one composition-root line.
- `fxtwitter-source.ts` — `FxTwitterTimelineSource`, an `axios` client for an FxTwitter-compatible JSON API (`GET {base}/2/profile/{handle}/statuses`), with a bounded redirect count, a response-size cap, and a descriptive User-Agent. Each attempt carries **two** time limits: axios's `timeout` (an inactivity timer) and an `AbortSignal.timeout` acting as the absolute deadline — without the latter a response that trickles bytes resets the inactivity timer indefinitely and wedges the serial poll loop. A read is wrapped in `retryFetch` (C1) at 3 attempts from a 1 s backoff, deliberately shorter than that helper's default because the poll loop returns in minutes: a transient 502 or dropped socket is retried, while a 404, a 400, and — via a narrowed `shouldRetry` predicate — a **429** all fail immediately. Retrying a rate-limit would answer "you are sending too much" by sending three times as much within seconds; the poll interval is the correct backoff. `apiBaseUrl` is operator-configurable so a self-hosted instance can replace the public host. It is built around four undocumented upstream behaviours verified against the live API: **`count` is ignored** (a full page always comes back, so the caller caps what it acts on); **`since` gates the status code but does not filter** (it decides `204` versus `200`, and a `200` still carries the whole page including posts older than `since`, so de-duplication is the caller's job); **`since` is a strict `>`** (a post created in the same second as the newest one already seen would stay invisible while that cursor holds, which is why the plugin periodically re-reads with no `since`); and **entries are not ordered by `created_timestamp`** (a repost carries the original post's timestamp and id, so the sequence is monotonic only once reposts are dropped). The response is validated with zod one entry at a time (`.passthrough()`), so an unrecognised entry kind is skipped rather than failing the page — but a non-empty page that yields no usable entry is reported as `X_FEED_INVALID_RESPONSE` rather than as "nothing new", so an upstream schema change surfaces instead of silently killing the feed. `validateStatus` accepts only 200 and 204, so 400 / 404 / 5xx reach the translator.
- `error-translator.ts` — maps `axios` transport/HTTP failures to `XFeedError` (`X_FEED_TIMEOUT` / `X_FEED_RATE_LIMITED` / `X_FEED_UPSTREAM_5XX` / `X_FEED_NOT_FOUND` / `X_FEED_FETCH_FAILED`) and constructs `X_FEED_INVALID_RESPONSE`. `404` is coded apart from the transient failures because it means the handle no longer exists — renamed, suspended, or a config typo — and stays broken until an operator edits the config.

## Notes

`@core/*` modules never import from `src/infra/`. The dependency direction is one-way: composition roots and adapters depend on core, never the reverse.
