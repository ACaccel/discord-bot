# C5 — Infra Adapters

## Responsibility

Isolates third-party SDKs behind typed adapters so the rest of the codebase depends only on stable interfaces. Four families: Mongo connections, LLM providers, link-preview providers, and small Discord-side adapters.

## Mongo

`src/infra/mongo/connection-manager.ts` exposes `ConnectionManager` with two implementations: `MongoConnectionManager` (real Mongoose) and `StaticConnectionManager` (test injection).

- `getConnection(guildId)` opens or returns the cached connection for a guild.
- Failure classification reuses `isTransient(error)` from `src/persistence/error-translator.ts` (`DATABASE_TIMEOUT` / `DATABASE_NETWORK` are transient, others persistent).
- Transient failures retry with bounded exponential backoff via `RetryPolicy` (default: 3 attempts, 200 ms initial, 2 s cap; injectable through the constructor).
- When retries are exhausted or a persistent error occurs, the manager marks the `guildId` disabled with a generated `traceId` and logs one operator-level line.
- `isDisabled(guildId): DisabledGuildState | undefined` exposes the disabled state (`traceId` plus the classified `DatabaseError`) for handlers and BaseBot to read; subsequent `getConnection` calls short-circuit with the same error. `close` / `closeAll` clear the marker.
- Bots sharing the same base URI share one disabled set (one physical database, one failure).

## LLM

`src/infra/llm/` implements the Provider Strategy:

- `types.ts` — `LlmProvider` interface plus shared request/response shapes. `DEFAULT_MODELS` seeds each provider's cheapest current chat model (xai `grok-4-1-fast-non-reasoning`, openai `gpt-5-nano`, anthropic `claude-haiku-4-5`, gemini `gemini-2.5-flash-lite`); `DEFAULT_SETTINGS` enables web search by default.
- `openai-provider.ts`, `anthropic-provider.ts`, `gemini-provider.ts`, `xai-provider.ts` — concrete `LlmProvider` implementations.
- `registry.ts` / `default-registry.ts` — provider registry assembly.
- `llm-service.ts` — facade used by the `llm-chat` plugin.
- `models-catalog.ts` — `ModelCatalog` (pure cache plus API-key map). Registered via `ctx.registerInstance(TOKENS.ModelCatalog, ...)` inside `LlmChatPlugin.init`; consumed by handlers through `bot.modelCatalog?.list(provider)`. `list(provider)` is the synchronous cache view capped to the 25-option Discord select-menu limit (built for the 3-second window); `listLive(provider)` is the awaited authoritative fetch consumed by the default-model resolver and returns the _full_ uncapped list (the menu cap must not hide the cheapest model from price ranking), while the cache it refreshes stays capped.
- `default-model-resolver.ts` — `DefaultModelResolver`. Holds the per-provider default chat model, seeded from `DEFAULT_MODELS` and re-derived by `refresh()` to the cheapest still-listed priced model (live list ∩ `pricing.ts`). Conservative: a failed/empty fetch or an all-unpriced list keeps the previous default. Registered via `ctx.registerInstance(TOKENS.DefaultModelResolver, ...)` in `LlmChatPlugin.init`; consumed by `ai_whitelist_add` through `bot.defaultModelResolver?.current(provider)`.
- `error-translator.ts` — translates provider errors to `LlmProviderError`.
- `pricing.ts` — token-cost lookup table plus `cheapestModel(candidates)` (lowest input price, output price as tie-breaker, unpriced candidates ignored).
- `selfhosted-client.ts` — `SelfHostedLlmClient`, a standalone outbound adapter for a lightweight self-hosted LLM HTTP endpoint (consumed by the `llm-auto-reply` plugin, C8). It deliberately does **not** implement `LlmProvider`: the endpoint takes a single baked `user` message (`{ messages: [{ role, content }] }`) and returns `{ status, response }` with no API key, model, or temperature. `reply(transcript)` returns `Result<string, ExternalServiceError>` — timeout, HTTP error, malformed body, and non-`success` status are all mapped into the shared `errors:llm.*` taxonomy so callers stay silent on failure. Uses `axios` with a per-request timeout and validates the response body with zod.

## Link Preview

`src/infra/link-preview/` implements a second Provider Strategy, mirroring the LLM layer, for the `social-link-preview` plugin (C8). A provider produces neutral data only — Discord-specific assembly (embeds, replies, suppression) belongs to the consuming plugin, so this layer stays free of message I/O.

- `types.ts` — the `LinkPreviewProvider` Strategy (`canHandle(url)` pure predicate + `build(url, ctx)` returning a `Result`) and the `LinkPreviewResult` discriminated union. The union carries the two preview mechanisms: `{ kind: 'rewritten-url' }` (reply with an embed-proxy URL so Discord unfurls a playable video — a bot-authored embed cannot render playable video) and `{ kind: 'card' }` (a neutral `PreviewCard` the plugin renders into a static embed). `build` returns `Ok(null)` for "matched the host but not previewable" and `Err(LinkPreviewError)` for upstream/parse failure; it never throws.
- `registry.ts` — `LinkPreviewProviderRegistry`. Unlike the LLM registry (keyed by enum name), providers are matched against an arbitrary URL, so it holds an ordered list and `findProvider(url)` returns the first whose `canHandle` accepts it. Registration order is priority.
- `default-registry.ts` — `createDefaultLinkPreviewRegistry(deps)` wires every provider in priority order (one line each). Each rewrite provider takes a priority-ordered `proxyHosts` LIST (operator-overridable) and shares one `OgClient`; `enabledProviders` is the per-source kill-switch. Defaults: Twitter/X `[fxtwitter.com, vxtwitter.com]`, Instagram `[kkinstagram.com, uuinstagram.com]`, Threads `[viewthreads.com, vxthreads.net]`, Facebook `[facebed.com, fixacebook.com]`, Reddit `[vxreddit.com, rxddit.com]`, Bilibili `[vxbilibili.com, bilibiliez.com]`.
- `providers/rewrite-provider.ts` — `createRewriteProvider(spec)` Template Method shared by the six URL-rewrite providers. It is no longer a pure string transform: `build` **validates before posting** — it probes each `proxyHost` in order, fetching the candidate's OpenGraph via `OgClient` (Discord crawler UA), and picks the best by score (`scoreMeta`): a host with `og:video` wins immediately (playable); else the first host with an image; else the first text-only host; else `Ok(null)` so the orchestrator skips and **no bare/dead link is ever posted**. `scoreMeta` rejects **login-wall / not-found / proxy-error placeholders** (`isJunkPreviewTitle`, checked against both `og:title` and `og:description`: "Log in or sign up to view", "Content not found", vxReddit's "Failed to get data from Reddit" / bare proxy-name title, ...) as `none` — a login-gated Facebook post or a Reddit-API-failed proxy returns an OG with only such a placeholder and no media, and scoring it as a text card would post a broken embed. Per-host probe failures log at debug (proxy flakiness is expected), never as `Err`. The whole sequence is bounded by `ctx.budgetMs` (cumulative) on top of `ctx.timeoutMs` (per host). `canHandle` stays a pure predicate.
- `providers/{twitter,instagram,threads,facebook,reddit,bilibili}.ts` — supply `matches`, the `proxyHosts` list, and `toProxyUrl` (Twitter/Instagram/Threads/Reddit drop the query; **Facebook preserves it** — `watch`/`permalink`/`story` ids live there; **Bilibili keeps only `?p=`**, the multi-part video selector, dropping bilibili tracking such as `spm_id_from`/`vd_source`). **Facebook is a composed provider**, not a thin spec: it additionally (a) **expands `/share/<type>/<token>` short links** — the proxies cannot resolve the opaque share token and serve a login wall, so the provider first chases Facebook's browser-UA redirect to the canonical `/videos/`/`/reel/` permalink (`OgClient.resolveCanonical`) and probes THAT (the only form that yields a playable video), then (b) **falls back to a static OpenGraph card** when no proxy can preview a Facebook link (the probe returns `null`) — scraping Facebook's own OG, which Facebook serves to the Discord crawler UA, and rejecting login-wall placeholders via the shared `isJunkPreview`. Reddit matches comment permalinks (`/r/<sub>/comments/<id>`, bare `/comments/<id>`) and the mobile `/r/<sub>/s/<token>` share form across reddit host variants (`www`/`old`/`new`/`np`/`m`/`amp`); its default `[vxreddit.com, rxddit.com]` leads with the verified-working `vxreddit` (rxddit/FixReddit is currently 502 on posts under Reddit's API limits, kept as a best-effort fallback). Instagram matches **both** the canonical `/reel|p|tv/<id>` and the author-prefixed `/<username>/reel/<id>` form (profile / share links use the latter; the prior anchored regex rejected it, so those links got no preview at all). Bilibili matches `(www.|m.)?bilibili.com` video pages (`/video/<BV…|av…>`) and rewrites onto BiliFix `vxbilibili.com` → BilibiliEZ `bilibiliez.com`, **dropping the path's trailing slash** (vxbilibili 307-downgrades a `/video/<BV>/` request to `http://`, which Discord's crawler refuses, so the no-slash form must be posted). **Bilibili is also a composed provider** (like Facebook): it matches `b23.tv` / `www.b23.tv` short links, whose opaque token carries no video id, and first expands them to the canonical `/video/<BV|av>` URL via `OgClient.resolveCanonical` (browser-UA redirect chase), proxying only when the resolved URL is a bilibili video page and skipping silently otherwise (live / dynamic / article / bangumi targets, or a failed resolution); `?p=` is preserved through resolution, tracking query dropped. Original-host-only matching excludes proxy hosts so an already-fixed link is left alone. Proxy domains are third-party services that churn (the prior `facebookez.com` became defunct and now redirects to an ad network; `fixthreads.net` was archived; `threadsez.com` now 307s to an `embedez.com` JSON download API that never serves OpenGraph, and `vxthreads.net` is intermittently unreachable, so the Threads default leads with the verified-working `viewthreads.com`) — the priority list + validation makes the layer self-correcting.
- `providers/bahamut.ts` — a fetching provider for `gamer.com.tw` (no public proxy). Scrapes OpenGraph via `OgClient` and maps the first image into a `PreviewCard`.
- `og-client.ts` — `OgClient`, the SSRF-safe OpenGraph fetcher and the single network boundary (used by both validation and Bahamut). It mirrors what Discord's unfurl accepts at a proxy URL — **either** an HTML page with OpenGraph tags **or** a redirect (for a bot UA) straight to a `video/*` / `image/*` file Discord embeds directly. So the response is **streamed** and classified by its final `Content-Type`: a media type is itself a playable preview and **no body is downloaded** (a reel `*.mp4` can be many MB); otherwise the body is read only up to `</head>` (or a byte cap) and `parseOpenGraph` runs — fixing both IG failure modes the old buffered fetch hit (`kkinstagram` redirects the bot UA to a multi-MB `*.mp4`, and the `uuinstagram` fallback lands on a ~900 KB `instagram.com` page; the prior `maxContentLength` body cap rejected both, so IG returned nothing). `axios` follows up to `SAFE_MAX_REDIRECTS` (3) hops with a `beforeRedirect` guard (`isUnsafeRedirectHost`, exported + unit-tested) that refuses any hop to a private / loopback / link-local / unspecified / CGNAT IP (v4, v6, IPv4-mapped/compatible, NAT64), an internal hostname (incl. trailing-dot FQDN forms), or a non-`http(s)` scheme — so a crafted redirect to e.g. `169.254.169.254` is blocked. Each redirect hop's target is recorded; when the body fetch itself fails but a hop targeted a media file (`*.mp4`/`*.jpg`/…), it still counts as a hit — because **Discord**, not the bot, performs the unfurl, so a CDN our host cannot reach (datacenter-IP peering) but Discord can must not be a false negative. The default UA is the Discord crawler UA `Discordbot/2.0`. A separate `resolveCanonical(url, timeoutMs, provider?)` method follows the same SSRF-guarded redirect chain under a plain **browser** UA (Facebook only redirects a `/share/` short link to its canonical permalink for a non-crawler UA — the crawler UA gets a ready-made OG card at the share URL itself) and returns the post-redirect URL **without reading the body**, used by the Facebook provider to expand share links and by the Bilibili provider to expand `b23.tv` short links. Its optional `provider` argument (default `'facebook'`) tags any error on the Err rail with the calling source. (DNS-rebinding of a public hostname to a private IP is the one residual SSRF gap, accepted as low-risk.) `parseOpenGraph(html)` (pure, exported) extracts all `og:image*`/`twitter:image` into `images[]`, the best `og:video*` into `video`, plus title/description/url/siteName, scanning only the `<head>` via a bounded regex (no HTML-parser dependency). Attribute values may be double-quoted, single-quoted, or **unquoted** — vxbilibili emits unquoted `property=`/`content=` attributes (and sometimes omits the space before the next attribute), which a quoted-only matcher would drop, silently losing the preview. A small bounded in-memory cache (TTL ~10 min, success-only, FIFO eviction) avoids hammering flaky proxies when the loop fans out or a link is reposted (a degraded-but-200 page is therefore cached for the TTL, briefly suppressing that URL's preview even after the proxy recovers — an availability trade-off). SSRF: the candidate host always comes from the operator-configured `proxyHosts` allow-list (or `canHandle`'s host set) — only the path/query is user-derived; worst-case latency per URL is bounded by `proxyHosts.length × timeoutMs`, capped by `validationBudgetMs`.
- `error-translator.ts` — maps `axios` transport/HTTP failures to `LinkPreviewError` (timeout / rate-limited / 5xx / fetch-failed) and constructs the "no usable OpenGraph tags" `LINK_PREVIEW_INVALID_RESPONSE`.

## Discord adapters

`src/infra/discord/`:

- `attachment-archive.ts` — uploads message attachments to an archive channel for backup workflows.
- `channel-log.ts` — operator log channel adapter.

## Notes

`@core/*` modules never import from `src/infra/`. The dependency direction is one-way: composition roots and adapters depend on core, never the reverse.
